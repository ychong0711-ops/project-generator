## 1. 로컬 동작 확인 (필수)

### 왜 필요한가

의존성을 손봤습니다. React 19와 peer 충돌로 **`npm ci` 자체가 실패하던 상태**였기 때문에
`react-i18next`와 `@testing-library/react`를 올렸고, 보안 취약점 때문에 `vite`도 올렸습니다.

```
react-i18next          ^23.11.0  ->  ^15.7.4   (React 19 peer 충돌 해소)
@testing-library/react ^15.0.0   ->  ^16.3.0   (React 19 peer 충돌 해소)
vite                   7.3.2     ->  ^7.3.6    (보안 권고 2건 해소)
```

샌드박스(Linux)에서는 전부 통과했지만, 사용자 환경은 Windows입니다
(초기 빌드 로그의 `C:/embedded/automotive-embedded-project-generator` 경로로 확인).
`node_modules`는 커밋 대상이 아니므로 로컬에서 한 번 받아 확인하셔야 합니다.

### 명령

```bash
git checkout arena/01a00b33-project-generator
git pull

rmdir /s /q node_modules        # Windows. 기존 의존성 제거 (중요)
npm install

npm run typecheck               # 통과해야 함
npm test                        # 163개 통과해야 함
npm run build                   # dist/index.html 생성
npm run dev                     # 브라우저에서 화면 확인
```

> `run-all.bat`을 실행해도 됩니다. 다만 이 스크립트에는 타입 체크가 이미 포함되어 있고,
> `npm run build`가 내부에서 `tsc --noEmit`을 한 번 더 돌리므로 타입 체크가 두 번 수행됩니다.
> 동작에는 문제 없습니다.

**`node_modules` 삭제를 빼먹지 마세요.** 기존 폴더에 구버전 패키지가 남아 있으면
peer 충돌이 재현될 수 있습니다.

### 화면에서 확인하면 좋은 것

의존성 교체와 직접 관련된 부분입니다.

- **우측 상단 KO / DE / EN 버튼** — `react-i18next` 메이저 업그레이드 영향권입니다.
  눌렀을 때 상단 메뉴와 푸터 문구가 바뀌는지 확인해 주세요.
- **탭 전환** (홈 / 생성기 / 대학 / 로드맵 / 포트폴리오 / 경쟁력 / 실습 / 가이드)
  — `Suspense` 구조를 8중 중첩에서 단일로 정리했습니다.
- **CodeLab의 오프라인 실행** — `float x = 2.5;`가 이제 동작합니다(기존에는 오류).

## 3. CI 워크플로 패치 적용 (권장, 2분)

### 왜 제가 못 했나

Arena의 GitHub App 토큰에 `workflows` 스코프가 없습니다. 워크플로 파일이 포함된 푸시는
파일 하나가 아니라 **푸시 전체가 거부**되기 때문에, 해당 파일만 되돌리고 나머지를 올렸습니다.

### 지금 문제가 되나

**타입 오류 검출은 이미 됩니다.** `package.json`의 `build`를 `tsc --noEmit && vite build`로
바꿔놨기 때문에 CI의 Build 단계에서 잡힙니다.

다만 **더 중요한 문제가 하나 있습니다.** 현재 워크플로는 `branches: ["main"]`만 감시해서
**작업 브랜치에서는 CI가 아예 돌지 않습니다.** 패치에 이 수정도 포함했습니다.

### 적용 방법 (아무거나 하나)

**A. 웹 UI** — 저장소 → `.github/workflows/ci.yml` → 연필 아이콘 →
`- name: Run tests` **위에** 아래 삽입:

```yaml
    - name: Type check
      run: npm run typecheck

```

그리고 상단 `on:` 블록을 아래로 교체:

```yaml
on:
  push:
    branches: [ "main", "arena/**" ]
  pull_request:
```

**B. 패치 적용** — 저장소에 넣어둔 패치를 쓰면 위 두 가지가 한 번에 적용됩니다.
`git apply --check`로 클린 적용을 검증해 뒀습니다.

```bash
git apply docs/ci-typecheck.patch
git commit -am "ci: 타입 체크 단계 추가 및 arena 브랜치 트리거"
git push
```

**C. 권한 부여** — Arena 설정에서 GitHub 연결을 재인증하며 `workflows` 스코프를 허용하면
다음 세션부터 제가 직접 처리할 수 있습니다.

## 4. union 처리 방침 결정 (판단만 주시면 됩니다)

오프라인 C 엔진의 union은 근사 구현입니다. 스칼라 멤버들이 하나의 값을 공유하는 방식이라
**타입별 폭(width) 개념이 없습니다.**

```c
union U { int a; char b; };
v.a = 321;
printf("%d %d", v.a, v.b);
// 실제 C : 321 65   (하위 1바이트만 char 로 읽힘)
// 현재    : 321 321
```

값이 0~255면 우연히 맞고, 넘어가면 어긋납니다.

**영향 범위는 좁습니다.** 앱이 제공하는 C 샘플·실습 코드에 union 사용은 0건입니다
(`samples-a.ts`, `samples-b.ts`, `labs.ts` 전수 확인). 사용자가 CodeLab에 직접 타이핑하는
경우로 한정되고, 그마저 온라인 모드(arm-none-eabi-gcc)라는 정확한 대안이 있습니다.

| 안 | 내용 | 작업량 | 위험 |
|---|---|---|---|
| **A (권장)** | 현행 유지 + union 선언 시 "근사 구현이므로 온라인 모드로 검증하세요" 경고 출력 | 30분 | 없음 |
| B | 타입별 폭 마스킹 (`char`는 `& 0xff` 등). 정수 계열은 정확해짐 | 2~3시간 | 낮음 |
| C | `ArrayBuffer` + `DataView` 기반 실제 바이트 레이아웃. 전부 정확 | 1~2일 | 있음 (struct 런타임까지 수정 필요) |

**A를 권합니다.** 사용자가 조용히 틀린 값을 믿는 상황만 막으면 충분하다고 봅니다.
원하시는 안을 알려주시면 이어서 작업하겠습니다.

자세한 케이스별 측정 결과는 `docs/후속-확인사항.md`에 있습니다.

## 참고: 제가 이미 처리한 것

따로 하실 일 없습니다. 확인만 하시면 됩니다.

- **보안 취약점 2건 해소** — Windows 개발 서버 관련 권고였습니다
  (`vite`의 `server.fs.deny` 우회, `esbuild` 임의 파일 읽기). 사용자가 Windows 환경이라
  실제 해당되어 `vite@7.3.6`으로 올렸습니다. 현재 `npm audit` 결과 **0건**입니다.
- **빌드 실패 복구** — `I18nProvider`가 존재하지 않는 export를 import하던 문제.
- **데이터 손상 버그 3건** — 백업 복원 시 이중 인코딩, 컴파일러 진단 파서의 인덱스 오프바이원,
  GitHub 배포의 잘못된 API 파라미터.
- **인터프리터 struct/union 구현** — 파싱만 되고 실행은 안 되던 미완성 코드 재작성.
- **`float` 키워드 누락 수정** — `float x = 2.5;`가 오류로 실패하던 선행 버그.
- **테스트 인프라 복구** — vitest 설정에 jest 옵션명을 써서 setup이 로드되지 않던 문제.
  테스트 123개(5 실패) → **163개 전부 통과**.
- **저장소 정리** — 커밋돼 있던 빌드/테스트 로그 8개와 `.bak` 파일 제거 후 `.gitignore` 등록.
